# Auditul 4 — 24 septembrie 2026

Runda de audit de dupa trei schimbari mari, facute in 22–24 septembrie:

1. **banii**: plata cu cardul a fost scoasa cu totul, iar administratorul confirma incasarea
   (numerar sau transfer);
2. **conturile**: identitatea nu mai este adresa de email, ci numarul de telefon, iar contul il
   face administratorul;
3. **conducerea**: presedintele si cenzorul au mandate in aplicatie si un panou doar de citire.

Metoda este cea din rundele trecute: trei fire de analiza in paralel, fiecare constatare verificata
apoi pe stiva locala inainte de a fi reparata. "Totul verde" nu este dovada de corectitudine: suita
trecea si inainte de fiecare dintre problemele de mai jos.

Numerotarea este pe zone: **A** conturi, **B** bani, **C** conducere.

## A. Conturile pe numar de telefon

| ID | Gravitate | Pe scurt |
| --- | --- | --- |
| A1 | grav | inscrierea prin API este deschisa: cineva isi face singur cont pe adresa interna a unui numar si primeste apartamentul cand administratorul adauga acel numar |
| A2 | grav | locatarul isi poate schimba singur numarul din profil (`grant update (nume, telefon)`) si poate prelua contul urmator creat pe numarul altuia |
| A3 | mediu | parola generata are ~22 de biti de entropie si omul nu si-o poate schimba niciodata |
| A4 | mediu | "Parola noua" nu inchide sesiunile deschise si merge si pentru un acces deja inchis |
| A5 | mediu | `profiluri.telefon` nu este nici unic, nici normalizat in baza |
| A6 | mediu | numerele scrise "+40 0722 ..." sunt respinse, iar ecranul nu spune de ce |
| A7 | mediu | dupa o creare cazuta la mijloc, ecranul spune "avea deja cont", desi nimeni nu stie parola |
| A8 | mediu | anonimizarea lasa numarul de telefon in `auth.identities` |
| A9 | minor | erorile serverului pleaca netraduse catre administrator |
| A10 | minor | domeniul intern (`telefon.adminbloc.ro`) este unul real, inregistrabil |
| A11 | minor | `profiluri.email` a ramas in schema, mereu null, cu un comentariu care nu mai e adevarat |

## C. Presedintele si cenzorul

Raspunsul la intrebarea centrala — poate conducerea sa schimbe ceva? — este **nu**: fiecare comanda
de scriere expusa de aplicatie cere `private.*_administrate()`, iar granturile pe tabele sunt
acoperite de politici. Problemele sunt de alt fel: ecrane care mint, drepturi care nu se sting la
timp si divergente intre surse.

| ID | Gravitate | Pe scurt |
| --- | --- | --- |
| C1 | grav | Sesizari: pe server conducerea nu vede nimic (H11), in demo vede tot — si testele valideaza demo-ul, deci ecranul ramane gol fara sa spuna de ce |
| C2 | grav | presedintele care locuieste in bloc isi pierde toate ecranele de locatar: nu mai transmite index, nu mai face sesizari, nu mai voteaza |
| C3 | grav | `tests/e2e/roluri.spec.js` a ramas pe comportamentul vechi: trei teste pica (confirmat de rulare) |
| C4 | mediu | `cont-locatar`, pe drumul "conducere", creeaza contul inainte sa verifice ca cel care cere este administrator |
| C5 | mediu | `numeste_in_conducere` alege asociatia cu `limit 1`, fara ordine: mandatul poate ajunge pe alta asociatie a aceluiasi administrator |
| C6 | mediu | `incheie_mandat` pune `activ_pana = activ_din + 1`, deci un mandat incheiat in ziua in care a inceput mai da drepturi pana maine |
| C7 | mediu | renumirea suprascrie mandatul precedent: istoricul promis in comentariu nu ramane |
| C8 | mediu | administratorul se poate numi pe el insusi cenzor, adica exact separarea pe care functia exista sa o apere |
| C9 | mediu | doua butoane au scapat de paza de citire ("Trimite reminderele", "Calculeaza lista pe apartamente"): baza le refuza, dar omul vede un mesaj tehnic |
| C10 | minor | `marcheaza_anunt_citit` este singura comanda de scriere deschisa conducerii (efect practic nul) |
| C11 | minor | politica de storage pe poze a ramas pe `blocuri_conduse()` desi H11 a inchis tabela sesizarilor |
| C12 | minor | un mandat cu `activ_din` in viitor apare in ecran ca fiind in curs |
| C13 | minor | telefonul unui cenzor din afara blocului ajunge in datele oricarui locatar (`incarca()` aduce `membri_asociatie` pentru toti) |
