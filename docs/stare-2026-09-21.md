## CI

Ruleaza pe fiecare pull request si la push pe `main`, in aproximativ 8 minute:
lint, teste unitare si Deno; migratii de la zero, pgTAP si integrare; e2e pe
patru masini in paralel. Pe PR, e2e doar pe telefon; desktop la push pe `main`.

Prima rulare de CI din viata proiectului a gasit opt probleme pe care patru
straturi de teste, rulate pe un singur laptop, nu le vazusera: fus orar,
teste care depindeau unele de altele, un test aleator, un defect real de
interfata si o cursa in baza. Toate reparate.

## Cum se reia

1. PR-ul ramurii `repara-audit3-restul`, verde pe CI.
2. `supabase db push` pentru migratiile noi, **inainte** de merge: ecranele noi
   (citirile de verificat, avansul, motivul respingerii) folosesc baza noua.
3. Merge; Vercel publica frontendul.
4. Advisorii de securitate pe productie: avertismentele pentru `numar_ro` si
   `rls_auto_enable` trebuie sa dispara.
5. Deciziile pentru K7 si K24.
6. Apoi runda 6 a auditului: cod si end-to-end, cu aceeasi instructiune —
   „totul verde" nu e dovada de corectitudine.

## De stiut

- `supabase migration new` asteapta SQL pe intrarea standard cand aceasta nu e
  un terminal; se ruleaza cu `</dev/null`.
- Un `supabase db reset` poate lasa oprit containerul edge runtime; seed-ul
  cade atunci cu „name resolution failed". `docker start
  supabase_edge_runtime_AdministratorBloc` il reporneste.
- Dupa orice `db reset`, `npm run seed` inainte de testele de integrare si e2e.
